# Методы из исследований журналов событий

По просьбе пользователя при остановке роста качества проверяем подходы
из первичных научных публикаций и официальных репозиториев. Результаты
других задач не считаются ожидаемым score этого чемпионата.

1. [LogFormer, AAAI 2024](https://arxiv.org/abs/2401.04749),
   [официальная реализация](https://github.com/HC-Guo/LogFormer).
   Метод обучает transformer для журналов и переносит знания между
   доменами через adapters. Для нашей задачи адаптируем представление
   последовательности, дополняя его тремя supervised heads: класс,
   успех и начало сбоя. `sequence_v6` — собственная малая модель над
   структурными признаками; она не воспроизводит весь LogFormer и не
   использует чужие готовые веса. Перенос adapters пока не проверен.

2. [LogGD](https://arxiv.org/abs/2209.07869).
   Авторы представляют события графом, чтобы учитывать отношения,
   которые теряются в счётчиках и последовательности. В нашей задаче
   полезны связи задачи, исполнителя, результата и зависимости.
   Проверенные `relations_v5` используют явно рассчитанные связи.
   Следующее расширение — внимание с учётом рёбер; это гипотеза,
   а не уже достигнутый результат GNN.

3. [Drain, ICWS 2017](https://pinjiahe.github.io/files/pdf/research/ICWS17.pdf),
   [официальный Drain3](https://github.com/logpai/Drain3).
   Алгоритм объединяет сообщения в шаблоны, заменяя переменные части.
   Планируем проверить частоты и переходы между шаблонами как признаки
   поверх связей v5. Парсер обучается только на обучающих runs; на
   проверочных данных используется режим match без создания кластеров.

4. [StackingClassifier, официальная документация scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.StackingClassifier.html).
   Итоговый классификатор обучается по cross-validated предсказаниям,
   чтобы не учиться на искусственно безошибочных ответах базовой модели
   на её собственных training rows. Для выбора основного сбоя адаптируем
   этот принцип: три внутренние group folds дают кандидатов для
   training runs, затем Lambdarank выбирает один из семи классов по
   вероятностям, контексту и окну предполагаемого начала. Внешние
   проверочные runs исключаются из всех внутренних обучений.

Дополнительно просмотрены исследования именно сбоев систем агентов:
[Who&When, ICML 2025](https://proceedings.mlr.press/v267/zhang25cq.html),
[AgentTrace](https://arxiv.org/abs/2603.14688),
[Adaptive Influence Graphs](https://arxiv.org/abs/2608.24361) и
[MP-Bench](https://arxiv.org/abs/2603.25001).
Графы потока данных и выбор кандидата применимы как представления.
Правило «самая ранняя ошибка — основная» из ряда этих задач переносить
нельзя: в Coordination Referee основной сбой может быть позже вторичного.
Публикации о нескольких допустимых трактовках также не доказывают
численный потолок score именно нашего датасета.

Ни один эксперимент не обращается к меткам test, run_id не используется
как признак. Внешние модели и методы должны улучшать локальную проверку,
прежде чем попасть в автономный пакет.
