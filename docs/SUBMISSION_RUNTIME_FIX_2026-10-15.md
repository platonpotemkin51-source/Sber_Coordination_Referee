# Исправление запуска submission, 15 октября 2026

## Причины и исправления

1. В новом `scripts/candidate_solution.py` была потеряна проверка обязательных
   полей рана, которая есть у коллеги и описана в `docs/faq.md`. Площадка может
   подавать урезанный smoke-файл. Отсутствие сообщений во всех 2 000 строках в
   последнем логе согласуется с таким входом; самого файла площадки у нас нет.
   Теперь до импорта моделей возвращается предусмотренный FAQ ответ
   `clean, success=1, fault_turn=-1`. Пустой файл с заголовком тоже допустим.
2. В смешанном входе строки без сообщений отделяются до извлечения признаков;
   остальные обрабатываются полноценным ансамблем. Порядок и строковые ID
   сохраняются, в том числе `0001`, `NA`, `null`. Кеши изолированы на каждый запуск.
3. Локально воспроизведено зависание загрузки весов Torch после вычислений
   LightGBM. Стек диагностики остановился в `_load_from_state_dict`. Инициализация
   PyTorch до загрузки LightGBM устранила его; число потоков ограничено.
4. В отдельном окружении со sklearn 1.5.2 воспроизведена следующая реальная
   ошибка: `LogisticRegression has no attribute multi_class`. Модель из sklearn
   1.8 больше не хранит это поле. При загрузке добавляется `multinomial`,
   соответствующее обученному семиклассовому классификатору. Веса не меняются.
5. В CPU-образе площадки Torch может отсутствовать. В этом случае решение
   использует существующие деревья, selector, ranker, текстовую модель и tree
   success. Это иной, сокращённый ансамбль; локальные метрики полного ансамбля
   к нему не относятся. Для полного решения следует выбрать GPU-образ с Torch
   2.5.1; сам inference по умолчанию работает на CPU.
6. В `TurnModel.predict` исправлена конкатенация пустого списка при отсутствии
   активных ходов. Произвольные ошибки моделей не подавляются общим try/except.

Все пять файлов весов в новом архиве побайтно соответствуют исходным локальным
артефактам. Обучение и подбор порогов в этой работе не выполнялись.

## Воспроизведение

```bash
python scripts/package_candidate_submission.py
python scripts/verify_candidate_submission.py \
  --archive outputs/submission-v15-runtime-fixed-20261015.zip \
  --test handoff/v15/assembled/data/competition/test.csv \
  --report outputs/runtime-verification.json
python -m pytest -q -rs tests --ignore=tests/test_templates.py
```

Проверяющий скрипт распаковывает ZIP в новую временную папку, убирает PYTHONPATH,
запускает `solution.py` из отдельного рабочего каталога без train и старых кешей.
Проверяет девять входов: урезанные 2 000 строк, файл только с заголовком, пустые
messages, null/пустые messages, реальные строки, смешанные строки, потерянные
intent/refs с обрезанным текстом, специальные строковые ID и полный тест на
4 000 строк. Для каждого проверяются exit code, ID и порядок, обязательные поля,
классы, бинарный success, целочисленный fault_turn и его границы. Ответы на три
реальные строки должны совпасть с соответствующими ответами полного прогона.

Из unit suite исключён экспериментальный `test_templates.py`: нет drain3,
который не входит в submission. Пять baseline-тестов автоматически пропущены
из-за отсутствия подготовленного demo train; это не проверки нового архива.
Полный Linux/Python 3.11 образ площадки локально не воспроизводился:
проверки проводились на macOS/Python 3.12.10 с Torch 2.5.1 и отдельно со
sklearn 1.5.2 из лога. Официальной оценки пока нет.
